# Планшеты / ПК: раскладка стола и масштаб

Связано с: `src/ui/GameTable.tsx`, `src/game/tabletViewportScale.ts`, `src/game/tabletTableScale.ts`, `src/game/pcHandScale.ts`, `docs/PC-CARDS-PROTECT-MOBILE.md`.

## Эталон калибровки планшет-стола (актуально)

**Все визуальные настройки планшет-версии стола** (Север `top: 25px`, сукно «100%» = бывший 125%-look, шкала 93–108%, зазоры Запад/Восток при 107–108%, подъём стола +8px (4p) и т.д.) снимались и принимались на экране:

| Параметр | Значение |
|----------|----------|
| Эталон | **1035 × 618** CSS-px |
| Код | `TABLET_LAYOUT_REF_WIDTH_PX` / `TABLET_LAYOUT_REF_HEIGHT_PX` в `src/game/tabletViewportScale.ts` |

**Если viewport отличается от эталона** — мягкий `zoom` всего `.game-table-root.game-table-tablet-pc` в обе стороны:

```
scale = clamp(min(width/1035, height/618), 0.72 … 1.45)
```

Класс `game-table-tablet-pc--viewport-scaled` при `scale ≠ 1`.  
**Не** фиксируем логический размер в 1035×618 (это обрезало стол из‑за `translateY` подъёма).

При правках планшет-layout ориентироваться на **1035×618**.

## Вердикт (аудит 110% / 4p)

**Режим 110% на 4 игроках — калибровка под ПК (ширина ≥1025px).**  
Наложения «везде исключены» — **нет**. Защита есть, но **разная по веткам**; единой проверки «не пересеклись ли рука и сукно» нет.

На обычных планшетах ≤1024px **карты руки не увеличиваются до 110%**.  
Риск тесноты / наследия boost — у **широких планшетов (≥1025)** и у **гибридной** зоны (ПК-оболочка + компактные карты).

## Два независимых флага (не путать)

| Флаг | Media Query | Что включает |
|------|-------------|--------------|
| `isMobileOrTablet` | `max-width: 1024px` | Компактные карты руки/взятки, сетка 2×2 |
| `isMobile` (`viewport-mobile`) | `max-width: 600px` **или** `(max-width: 1024px) and (max-height: 560px)` | Мобильный DOM, short-VH, **полный сброс** PC-scale (`pcScaleBoost = 0`) |

Планшет-тюнинг стола: `useTabletPcTableTuning` = `!isMobile && (isMobileOrTablet || isTabletPcShell)`.

**Важно:** класс `viewport-mobile` вешается только при `isMobile`. Высокий планшет 768×1024 — **не** `viewport-mobile`.

## Три класса устройств

### A. Телефон / низкий landscape (`isMobile`)

- Раскладка: мобильный DOM + short-VH / landscape-тюнинг.
- PC scale **выключен**.

### B. Гибрид: планшет (`useTabletPcTableTuning`)

Примеры: iPad; **эталон калибровки 1035×618**.

| Слой | Поведение |
|------|-----------|
| DOM стола | **ПК-оболочка** + `game-table-tablet-pc` |
| Карты руки / взятки | **Компакт планшета**, без ×1.10 |
| Масштаб сукна | шестерёнка на рамке, 93–108% (100% = изначальный) |
| Viewport &lt; 1035×618 | пропорциональный `zoom` всего стола |

### C. Полный ПК (`!isMobileOrTablet`, ширина ≥1025)

- Шестерёнка карт руки (PC hand scale); 4p UI **94–106%** (на ПК «100%» ≈ abs 105%; на планшете «100%» без ×1.05 — иначе рука крупнее калибровки; шаг 1%).

## QA-чеклист (планшет-layout)

1. DevTools **1035×618**: эталон, `tabletViewportScale = 1`.
2. DevTools **~900×550**: класс `game-table-tablet-pc--viewport-scaled`, всё пропорционально меньше.
3. Телефон `viewport-mobile`: без tablet viewport zoom.

---

## Правило правок

- Планшет-layout → калибровать на **1035×618**; меньшие экраны — через `tabletViewportScale`.
- Карты «только ПК» → `!isMobileOrTablet` **и/или** `@media (min-width: 1025px)`.
- Не считать, что «≤1024 ⇒ нет PC-shell».
